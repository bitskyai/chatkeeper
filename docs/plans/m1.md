# M1 implementation plan

Spec: ../design/architecture.md, sections 3–6 and 13; issue #1.
Execution: native, as requested. Go 1.26 floor uses the additionally installed mise toolchain;
M2 authentication/setup and M3 derived indexes are outside this milestone.

## Global constraints
Synthetic fixtures only; environment credentials never printed. Core depends only
on pluginapi. All storage access is confined and verified. No destructive API calls.

## Tasks
1. Contract and registry (`pkg/pluginapi`, `plugintest`): define v1 serializable
   snapshots, settings, event sink, lifecycle, content and cleanup contracts.
   Test manifest/schema validation and registry behavior before implementation.
2. Folder storage (`internal/storage`): canonical JSON, verified inventory, lazy
   attachments, dual writer locks, staged swap and recovery. Generate fixtures
   with prototype code, test exact roundtrip, tampering and process crashes first.
3. Runtime (`internal/core`): bounded coalescing queue, root reaction rule,
   guarded per-workspace supervision, startup/incremental/full repair and refresh.
   Test owner membership, event floods, hook panic/hang and workspace isolation.
4. Built-in adapter (`internal/plugins`): restricted HTTP API, bounded pagination,
   complete content/attachment validation, snapshot reuse, outbound websocket.
   Use fake API + socket tests and contract kit before implementation.
5. YAML, viewer, CLI (`internal/config`, `internal/web`, `cmd/chatkeeper`):
   strict neutral config plus plugin validation, environment-only secrets,
   verified read-only escaped viewer, run/check-config/backfill/verify/version.
   Test config rejection, viewer auth/CSP, and both event/polling e2e paths.
6. Delivery: architecture/noslack tests, SHA-pinned portable CI, porting mapping,
   README and MIT license. Run vet/staticcheck/race/cross-build/secrets scan,
   independent review, fix findings, open PR and wait for green CI.

## Interfaces
pluginapi owns Snapshot (manifest/messages/users/attachment sources), Workspace,
Plugin and Session. Storage consumes Snapshot and Key; core consumes Session and
Store, web consumes Store and ContentHooks. Config resolves registered plugins;
only CLI imports plugins/all. Tests may cross boundaries.

## Review focus
- Forged manifests, symlinks, unlisted objects and changed attachment bytes.
- Incomplete pagination/reply membership, cross-team API and event responses.
- Credentials on redirects or in error/log output.
- Crash at each rename/fsync boundary and cleanup journal pinning.
- Noncooperative plugin hooks and queue floods affecting healthy workspaces.

Each task uses failing behavioral tests, then implementation and full-suite checks.
