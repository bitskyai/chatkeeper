# M5 cleanup implementation plan

**Goal:** Implement issue #1's opt-in archive-then-delete cleanup and prove archives survive deletion and refresh.
**Architecture:** A platform-neutral engine uses the plugin cleanup driver. Folder storage holds the archive lock through verification, journal fsync and source deletion. Immutable snapshot hashes stay pinned; deletion timestamps live in the version-1 journal and are exposed as snapshot metadata.
**Spec:** docs/design/architecture.md §13, with the reviewed prototype own-bot policy superseding the original user-token-only requirement.

## Constraints and review focus
Default off; preview offline; whole-thread fail closed; no platform names in core; secrets and live identifiers never committed. Review ambiguous deletes, retries after source changes, concurrent refresh, malformed journal progress and preview/apply configuration changes.
